DinePosAI — BACKEND DATABASE SCHEMA (V1)

1. 🏢 MULTI-TENANT CORE MODEL
1.1 tenants
Stores each restaurant.
tenants (
 id UUID PK,
 name TEXT NOT NULL,
 country TEXT,
 timezone TEXT,
 currency TEXT DEFAULT 'JPY',
 tax_type TEXT, -- VAT / GST / NONE
 tax_rate NUMERIC(5,2),
 plan TEXT DEFAULT 'TRIAL',
 status TEXT DEFAULT 'ACTIVE', -- ACTIVE, SUSPENDED, EXPIRED
 trial_ends_at TIMESTAMP,
 created_at TIMESTAMP,
 updated_at TIMESTAMP
)
Indexes:
INDEX(country)
INDEX(status)

🔐 AUTH + SECURITY RULES

Authentication Flow
JWT access token (short lived)
Refresh token stored in sessions table
Device-based login enforcement

Session Rule
1 active session per user per device
New login invalidates old session

Data Ownership Rule (VERY IMPORTANT)
Every table MUST include:
tenant_id
Rule:
A tenant can ONLY access its own data.

Role-Based Access Control
Role
Access
SUPER_ADMIN
full system
MANAGER
full restaurant
CASHIER
POS only
KITCHEN
KDS only

SECURITY INDEX RULES
Always index:
tenant_id
order_id
user_id
status fields

⚡ CORE SYSTEM DESIGN PRINCIPLES
Multi-tenant isolation by tenant_id
Event-driven order updates (KDS sync)
Immutable financial records (payments, invoices)
Append-only audit logs
Offline-safe sync-ready structure
Stateless backend (JWT based)
