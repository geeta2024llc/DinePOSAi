You are a senior full-stack engineer. Build a secure, scalable web application following this exact architecture and workflow:

STACK
Frontend: Next.js (App Router), hosted on Vercel
Backend: Node.js (Express or Fastify), hosted on Render
Database: Supabase (PostgreSQL)
Media Storage: Cloudflare Docs R2
Payments: Stripe
Email: Resend
Analytics: PostHog

STEP-BY-STEP INSTRUCTIONS
1. PROJECT SETUP
Scaffold a Next.js project using create-next-app with TypeScript and App Router enabled.
Scaffold a separate Node.js backend (Express or Fastify) in its own repository or monorepo subfolder.
Initialize Git for both. Use a .gitignore that excludes .env files.
2. ENVIRONMENT VARIABLES
Create .env.local for the Next.js frontend and .env for the backend.
Define variables for: Supabase URL/key, Stripe keys, Resend API key, PostHog key, JWT secret, and backend API base URL.
On Vercel (frontend) and Render (backend), configure the same variables in the platform's environment settings for production.
Never hardcode secrets. Never commit .env files.
3. DATABASE (SUPABASE)
Connect to Supabase using the official JS client (@supabase/supabase-js).
Define schemas with proper data types, primary keys, foreign keys, and indexes.
Enable Row Level Security (RLS) on all tables.
Write RLS policies so users can only access their own data.
Use Supabase migrations to version-control schema changes.
4. MEDIA STORAGE
Use Cloudflare Docs R2 for all file uploads (images, documents, etc.).
Never store binary files in the database.
Generate signed/secure URLs for private media access.
Validate file types and enforce size limits on upload.
5. BACKEND API (NODE.JS ON RENDER)
Structure routes clearly: /api/auth, /api/users, /api/[resource].
Apply middleware in this order: CORS → HTTPS enforcement → rate limiting → auth verification → route handler.
Return consistent JSON responses: { success: true/false, data: {}, error: "" }.
Use environment-specific logging (verbose in dev, minimal in prod).
6. AUTHENTICATION & AUTHORIZATION (JWT)
Issue signed JWT access tokens (short expiry: 15–60 min) and refresh tokens (longer expiry: 7–30 days) on login.
Store access tokens in memory (frontend state); store refresh tokens in httpOnly cookies.
Verify JWT on every protected API route using middleware.
Implement role-based access control (RBAC): define roles (e.g., admin, user, guest) and enforce them per route.
Never expose sensitive fields (passwords, tokens) in API responses.
7. INPUT SANITIZATION & SECURITY
Validate and sanitize all incoming request bodies using Zod or Joi schemas.
Escape output to prevent XSS.
Use parameterized queries or Supabase's query builder — never raw SQL with user input.
Set security headers: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Strict-Transport-Security.
Enforce HTTPS in production. Redirect all HTTP to HTTPS.
Apply rate limiting on auth endpoints (max 5–10 requests/min per IP).
8. STRIPE INTEGRATION
Use Stripe Checkout or Payment Intents for payment flows.
Verify webhook signatures using stripe.webhooks.constructEvent() before processing any webhook event.
Store only Stripe customer IDs and subscription status in your database — never raw card data.
Handle these webhook events at minimum: checkout.session.completed, invoice.payment_failed, customer.subscription.deleted.
9. EMAIL (RESEND)
Use Resend to send transactional emails: welcome, password reset, payment confirmation, alerts.
Build email templates using React Email or plain HTML.
Always set a verified sender domain in Resend.
Queue or retry failed email sends — do not block the main request thread.
10. ANALYTICS (POSTHOG)
Initialize PostHog in the Next.js frontend using the JS SDK.
Capture key events: sign-up, login, purchase, feature usage, errors.
Respect user privacy: add a cookie consent banner and honor opt-outs (disable capture if declined).
Do not log PII (emails, names) as PostHog properties.
11. TESTING
Unit test all utility functions and business logic (Jest or Vitest).
Integration test all API endpoints (Supertest or similar).
End-to-end test critical flows: auth, checkout, core user journeys (Playwright or Cypress).
Test unhappy paths: invalid inputs, expired tokens, failed payments.
Achieve at least 70% code coverage before first production deploy.
12. DEPLOYMENT
Frontend (Vercel): Connect GitHub repo. Set env vars. Enable preview deployments for PRs.
Backend (Render): Connect GitHub repo. Set env vars. Enable auto-deploy on push to main.
Use a CI/CD pipeline (GitHub Actions) that runs lint, tests, and build before allowing merge to main.
Configure custom domains and ensure SSL certificates are active on both platforms.
13. MAINTENANCE
Monitor backend uptime with Render's built-in dashboard or UptimeRobot.
Set up error alerting (Sentry or similar) on both frontend and backend.
Schedule regular dependency audits (npm audit) and updates.
Back up the Supabase database weekly.
Review PostHog dashboards monthly to identify usage trends and issues.

CONSTRAINTS & PRINCIPLES
Keep it cost-effective: use free tiers where possible (Supabase free, Render free/starter, Vercel hobby).
Prefer simplicity over premature optimization.
Every secret lives in environment variables — no exceptions.
Every user-facing error must return a safe, non-leaking message.
Write self-documenting code; add comments only where logic is non-obvious.
Follow RESTful conventions. Document endpoints with brief inline comments or a README section.
